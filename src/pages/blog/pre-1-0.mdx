## What works well today

[YOUR TEXT: what you'd happily build with Velt now, and what you've seen work.]

<Callout kind="note" title="Facts you could use (remove before publishing)">
Classes, interfaces, generics, unions and narrowing, closures, `async`/`await`, destructuring,
optional chaining and `using` all compile. `.ts` files and Velt files import each other, so a
project can move over one file at a time ([Velt for TypeScript developers](/docs/book/ts-developers/)).
The standard library and the sqlite, postgres, redis and http-server
[packages](/docs/packages/).
</Callout>

## Where Velt is different from TypeScript

[YOUR TEXT: what's different on purpose, and why. This is where "familiar, not identical" lives.]

<Callout kind="note" title="Facts you could use (remove before publishing)">
The [Not supported](/docs/book/ts-developers/#not-supported) list on the TypeScript page:
`eval`, prototypes, run-time decorators (typed compile-time decorators work), `with`, and more.
`x!` is checked at run time. Check the list against the release you publish with: it shrinks
with every release (0.6 added default exports, operators and decorators).
</Callout>

# Streams

`ReadableStream`, `ReadableStreamDefaultReader` and `ReadableStreamDefaultController` are
globals, as in Node: no import (the module that defines them is `velt/io`). A stream is made from
a source whose `start`, `pull` and `cancel` callbacks the stream calls in the order the WHATWG
Streams standard gives, and is read with a reader, with `for await`, or as a `Response` body.

```ts
function numbers(): ReadableStream<number> {
  let n = 0;
  return new ReadableStream<number>({
    pull(controller) {
      n++;
      if (n > 3) {
        controller.close();
      } else {
        controller.enqueue(n);
      }
    },
  });
}

const reader = numbers().getReader();
for (;;) {
  const r = await reader.read();
  if (r.done) {
    break;
  }
  console.log(r.value); // 1, 2, 3
}
for await (const x of numbers()) {
  console.log(x); // 1, 2, 3
}
const body = new Response("<p>hi</p>").body; // a ReadableStream<Uint8Array>
if (body != null) {
  const r = await body.getReader().read();
  console.log(r.done ? "" : new TextDecoder().decode(r.value)); // <p>hi</p>
}
```

## Making a stream

`new ReadableStream<R>(source?, strategy?)`:

- The source's `start(controller)` runs in the constructor; `pull(controller)` runs once `start`
  has settled (a microtask later) and again whenever the queue is below
  `strategy.highWaterMark` (default 1; 0 pulls only for a waiting read), never two at once;
  `cancel(reason)` runs when a consumer cancels.
- Each callback may be `async` (the stream waits for its promise), and an error one throws errors
  the stream; a `start` that throws at once makes the constructor throw. As in JavaScript, what
  they throw may be any value: the stream errors with it as it is, and a `catch` around a read or
  the constructor gets an `unknown` (narrow it, or cast it: `(e as Error).message`).
- A `highWaterMark` that is negative or `NaN` is a `RangeError`.
- Once the stream is closed or errored it drops `pull` and `cancel`, so a source whose callbacks
  hold the controller is freed with the stream.

The controller has `enqueue(chunk)` (a waiting read gets it, or it is queued), `close()` (reads
get the queued chunks, then `done`), `error(e)` (queued chunks are dropped and reads reject with
`e`, any value), and `desiredSize`. `enqueue` or `close` after `close` throws
`TypeError: Invalid state: Controller is already closed`.

`ReadableStream.from(iterable)` reads an async iterable such as an async generator, one value per
read (it is not read ahead: its high-water mark is 0). An error the generator throws reaches the
reader as an `Error` with its text.

## Reading

- `stream.getReader()` locks the stream (`locked`); a second `getReader()` throws
  `TypeError: Invalid state: ReadableStream is locked`.
- `reader.read()` gives `{ value, done: false }`, or `{ done: true }` once the stream is closed,
  and rejects once it errored. `read()` and `cancel()` do their work when they are called, as in
  JavaScript, not when they are awaited.
- `reader.releaseLock()` lets go: a waiting read rejects with `Invalid state: Releasing reader`,
  and `reader.closed` with `Invalid state: Reader released`. `reader.cancel(reason)` and
  `reader.closed` are as in JavaScript. A cancel reason is an `Error`, a `string` or `null`.
- `for await (const chunk of stream)` reads to the end. Leaving the loop early (`break`, `return`,
  a throw) cancels the stream and releases it; a read that rejects ends the loop with its error
  and releases the stream.
- `console.log(stream)` prints what Node prints:
  `ReadableStream { locked: false, state: 'readable', supportsBYOB: false }`.

## Bodies

`res.body` and `req.body` are a `ReadableStream<Uint8Array>` ([fetch](/docs/std/net/http/)),
pulled only as they are read. Each read of `res.body` gives a new stream object (in JavaScript it
is the same one). A `ReadableStream<Uint8Array>` is a body, as in Node: `new Response(stream)`,
`fetch(url, { method: "POST", body: stream })`. The stream is read when the body is, and a chunk
that is not a `Uint8Array` fails that read (`Received non-Uint8Array chunk`).

```ts
async function* chunks(): AsyncGenerator<Uint8Array> {
  yield new TextEncoder().encode("hello, ");
  yield new TextEncoder().encode("stream");
}

const res = new Response(ReadableStream.from(chunks()));
console.log(await res.text()); // hello, stream
```

## Differences from Node

- An `await` resumes as soon as its promise settles, before callbacks queued earlier
  ([async](/docs/reference/async/)), so code after `await reader.read()` can run before a `pull`
  that Node would have called first (the order of the `pull` calls themselves is Node's).
- A finished read is `{ done: true }`, which prints without `value: undefined`.
- Not supported yet: `WritableStream`, `TransformStream`, `pipeTo`, `pipeThrough`, `tee`, byte
  streams (`type: "bytes"`, BYOB readers), a strategy's `size` function,
  `values({ preventCancel })`, and an `async` source callback's synchronous part running at once
  (it runs when the stream waits for it, a step later than in Node).

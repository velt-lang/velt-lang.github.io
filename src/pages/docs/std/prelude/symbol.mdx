# The prelude: Symbol

JavaScript's `Symbol`, a global (`std/lang/symbol/index.velt`): unique values compared by identity, which
also name members of objects ([Symbols](/docs/reference/types/#symbols)).

| Member | Meaning |
|---|---|
| `Symbol(description?)` | a new symbol, different from every other one |
| `Symbol.for(key)` | the registry's symbol for `key`, the same on every call |
| `Symbol.keyFor(s)` | the key of a symbol `Symbol.for` made, else `undefined` |
| `s.description` | the description given to `Symbol(...)`, or `undefined` |
| `s.toString()`, `String(s)` | `Symbol(description)` |
| `Symbol.iterator`, `Symbol.asyncIterator`, `Symbol.dispose`, `Symbol.asyncDispose`, `Symbol.toStringTag`, `Symbol.hasInstance`, `Symbol.toPrimitive`, `Symbol.species`, `Symbol.isConcatSpreadable`, `Symbol.match`, `Symbol.matchAll`, `Symbol.replace`, `Symbol.search`, `Symbol.split`, `Symbol.unscopables` | the well-known symbols |
| `Symbol.add`, `sub`, `mul`, `div`, `rem`, `pow`, `bitAnd`, `bitOr`, `bitXor`, `shl`, `shr`, `ushr`, `neg`, `bitNot`, their `…Assign` forms (`Symbol.addAssign` …), `Symbol.index`, `Symbol.setIndex` | Velt's operator keys: a method with one of them defines an operator for its type ([Operator methods](/docs/reference/classes/#operator-methods)) |

```ts
const KEY = Symbol("key");

const a = Symbol("a");
console.log(a, a === Symbol("a"), a.description, typeof a); // Symbol(a) false a symbol
console.log(Symbol.for("k") === Symbol.for("k"), Symbol.keyFor(Symbol.for("k"))); // true k
const seen = new Map<symbol, number>();
seen.set(KEY, 1);
console.log(seen.get(KEY), String(Symbol.iterator)); // 1 Symbol(Symbol.iterator)
```

A module constant initialized with `Symbol("...")` or `Symbol.for("...")` is made once, when the
program is compiled, so every use of the constant is the same symbol (and `Symbol.for` at run
time gives the same one for that key). `Symbol(...)` called at run time makes a new
symbol that lives until the program ends, and `Symbol.for` keeps one per key.

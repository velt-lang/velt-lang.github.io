# The Velt Reference

This is the precise description of the Velt language: what the compiler accepts, what it
rejects, and what the compiled program does. For a guided introduction, read
[the Book](/docs/book/); for imported modules, the [standard library](/docs/std/).

Velt is **TypeScript compiled to native code**, with Rust-class performance, a multi-core runtime
and no garbage collector. Three rules shape every decision:

- valid TypeScript runs as it does in Node;
- where JavaScript's behavior is a trap (comparing `1 == "1"`, a forgotten `await`), the
  compiler stops and says what to write instead;
- TypeScript is the starting point, not the limit: Velt adds its own opt-in features wherever
  they make programs faster or safer (integer types, typed errors, `shared`, `extend`).

## Conventions

- This reference describes **what the compiler does**. Every code block marked as Velt is
  compiled by the documentation tests, and the behavior is pinned by the end-to-end tests in
  `tests/golden/`.
- **Planned** marks a decided design that is not built yet. Planned code is never shown as
  working.
- Error messages are quoted verbatim, so you can search for them.

## Contents

1. [Lexical structure](/docs/reference/lexical/) — programs, comments, literals, keywords, operators
2. [Types](/docs/reference/types/) — numbers, strings, equality, `null`, literal types, unions, discriminated
   unions, intersection, branded and indexed access types, enums, objects, arrays, tuples, maps

4. [Functions and closures](/docs/reference/functions/) — parameters, generics, arrows, captures

   `declare decorator function`, `@x`

    conditional imports
12. [Built-ins](/docs/reference/builtins/) — what is in scope without an import
13. [Diagnostics](/docs/reference/diagnostics/) — the format and wording of compiler errors
14. [TSX](/docs/reference/tsx/) — JSX syntax, the provider, typing of elements and components, async
    components, how elements are compiled
15. [System functions](/docs/reference/system-functions/) — `declare system function`: the C
    library, safely
16. [C functions and unsafe code](/docs/reference/c-interop/) — `declare c`, `unsafe` and
    `// SAFETY:`: C libraries in packages with native code
17. [Host functions](/docs/reference/host-functions/) — `declare host`: functions a JavaScript
    host provides to a WebAssembly module
18. [Source generators](/docs/reference/source-generators/) — `declare generated function`:
    bodies a library writes per type at compile time (experimental)

How Velt differs from TypeScript, item by item, is in
[Velt for TypeScript developers](/docs/book/ts-developers/).

## Planned changes at a glance

Decided direction that is not implemented yet. Each chapter says where it applies.

| Planned | Chapter |
|---|---|
| `weak` references and a compile-time warning for reference cycles | [Memory model](/docs/reference/memory/) |
| No `struct` keyword: a class covers what a struct does (structs already behave as objects) | [Classes](/docs/reference/classes/) |
| `extend`: module scoping | [Classes](/docs/reference/classes/), [Modules](/docs/reference/modules/) |
| TSX: elements in the props of a component that takes ownership of them (`children: JSX.Element`); everything else in [TSX](/docs/reference/tsx/) works | [TSX](/docs/reference/tsx/) |

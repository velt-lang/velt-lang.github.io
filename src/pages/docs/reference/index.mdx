# The Velt Reference

This is the precise description of the Velt language: what the compiler accepts, what it
rejects, and what the compiled program does. For a guided introduction, read
[the Book](/docs/book/); for imported modules, the [standard library](/docs/std/).

Velt is **TypeScript compiled to native code**, with Rust-class performance, a multi-core runtime
and no garbage collector. Three rules shape every decision:

- valid TypeScript runs as it does in Node;
- where JavaScript's behavior is a trap (comparing `1 == "1"`, a forgotten `await`), the
  compiler stops and says what to write instead;
- TypeScript is the starting point, not the limit: Velt adds its own opt-in features wherever
  they make programs faster or safer (integer types, typed errors, `shared`, `extend`).

## Conventions

- This reference describes **what the compiler does today**. Every code block marked as Velt is
  compiled by the documentation tests, and the behavior is pinned by the end-to-end tests in
  `tests/golden/`.
- **Planned** marks a decided design that is not built yet. It always links the design note,
  and planned code is never shown as working.
- Error messages are quoted verbatim, so you can search for them.

## Planned changes at a glance

Decided direction that is not implemented yet. Each chapter says where it applies.

| Change | Design |
|---|---|
| Semantics stage 3: `weak` references and a compile-time warning for reference cycles | [semantics — cycles](https://github.com/velt-lang/velt/blob/main/docs/internals/design/semantics.md#reference-cycles--without-a-collector) |
| The `struct` keyword removed (structs already behave as objects) | [semantics — JS fidelity](https://github.com/velt-lang/velt/blob/main/docs/internals/design/semantics.md#js-fidelity-decisions) |
| `extend`: retroactive `implements`, module scoping | [TypeScript alignment §4](https://github.com/velt-lang/velt/blob/main/docs/internals/design/ts-alignment.md#4-extend--full-power-zero-cost-module-scoped) |
| TSX: elements in the props of a component that takes ownership of them (`children: JSX.Element`); everything else in [TSX](/docs/reference/tsx/) works | [TSX design](https://github.com/velt-lang/velt/blob/main/docs/internals/design/tsx.md) |
